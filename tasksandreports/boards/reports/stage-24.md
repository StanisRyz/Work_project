## 2. Что сделано

### §1. Настройка приёма

- **Поля доски**: `intake_enabled`, `intake_sub_board`/`intake_column` (оба `SET_NULL`), `intake_due_days` (0–365 рабочих дней или NULL, ограничение `board_intake_due_days_valid`), `intake_hint` (до 500).
  - Колонка — рабочая колонка любой поддоски; поддоска выводится из неё.
  - Пусто, а также колонка, удалённая позже, — это `services.intake_target()`: первая рабочая колонка первой поддоски.
- **Поля карточек**: `BoardField.in_request_form` и `required_in_request`. Ограничение `board_field_required_in_form`: обязательное поле всегда в форме.
- **`BoardIntakeHandler`** (`board` `CASCADE`, `user` `PROTECT`, уникальность `unique_board_intake_handler`):
  - новую заявку получают разбирающие, которые ещё активные участники доски, иначе владелец (`intake_recipients()`);
  - `remove_board_member()` снимает человека и отсюда.
- **`update_intake()`** — единственный писатель:
  - право `can_manage_board()`, блокировка доски, архивная доска отклоняется;
  - колонка проверяется через `_board_working_column()`, разбирающие — только активные участники, поля — только живые поля этой доски;
  - «то же самое» ничего не пишет и не публикует (возвращает `False`);
  - изменение публикует `structure_changed` и сдвигает `updated_at` поддосок.
- **Страница «Приём заявок»** — `/work/boards/<board>/intake/`, пункт в «⋯» доски для управляющего. Обычная POST-форма:
  - включатель, колонка (`<optgroup>` по поддоскам), срок, подсказка;
  - разбирающие флажками;
  - для каждого поля «нет / в форме / обязательно».

### §2. Заявка

- **`BoardRequest`** — поля из задания, плюс `updated_at` (для ревизии `boards`).
- **Ограничения базы**:
  - `board_request_status_known`;
  - `board_request_card_only_when_accepted` — у `ACCEPTED` есть `card`, у остальных нет;
  - `board_request_duplicate_only_when_duplicate`;
  - `board_request_decision_matches_status` — у `NEW` нет решения (кто, когда, комментарий), у остальных есть кто и когда;
  - `board_request_rejection_has_reason`;
  - частичная уникальность `unique_board_request_card`.
- **`submit_request()`**:
  - право `can_submit_request()`: любой активный сотрудник, живая доска, приём включён — проверяется под блокировкой доски;
  - отказы: «Эта доска сейчас не принимает заявки.», «Доска в архиве — заявки на неё не принимаются.»;
  - название обязательно (до 200), описание до 4000;
  - поля формы разбираются тем же `_parse_value()`, что значения карточки. Обязательное пустое поле — `FieldValueError` с именем поля, ключи вне формы игнорируются;
  - в `field_values` хранится JSON: текст, число десятичной строкой, дата ISO, id варианта.
- **`withdraw_request()`**: только автор, только `NEW`; статус `WITHDRAWN` с кем и когда.
- **Видимость для автора-не участника**: название доски, подсказка, поля формы; своя заявка и её судьба — как проекция. Карточек, колонок и участников он не видит, ссылки на доску у него нет.

### §3. «Заявки» для всех

- **`/work/requests/` (`boards:requests`)** — вне рамки досок, для любого вошедшего сотрудника:
  - «Подать заявку» — живые доски с приёмом и их подсказка;
  - «Мои заявки» — номер, название, доска, дата, статус, «что с ней».
- **«Что с ней»** у принятой заявки — код карточки, колонка (`card_column()` по статусу задачи) и «В работе / Выполнена / Отменена». Ссылка на карточку только у читающего доску. У отклонённой — причина, у дубля — код карточки. «Отозвать» новую заявку — через общее окно.
- **Форма** `/work/requests/<board>/new/`: название, подробности, желаемая дата и поля доски (обязательные со «*» и атрибутом `required`). Доска без приёма — 404.
- **Страница заявки** `/work/requests/item/<pk>/` (`boards:request_detail`): автор и читатели доски, остальным 404. Того, кто читает «Входящие», перенаправляет туда.
- **Навигация**:
  - пункт первого уровня «Заявки» после «Доски» — ленивый `boards.context_processors.requests_access` (`SimpleLazyObject`, одно `EXISTS`);
  - карточка «Заявки» в «Быстром доступе» по тому же правилу `can_use_requests()`;
  - таблица навигации в `AGENTS.md` обновлена.
- **URL**: приложение `boards` теперь подключено один раз на `/work/`: `boards/` — доски, `requests/` — заявки, одно пространство имён `boards:`. Адреса досок не изменились.

### §4. «Входящие»

- **Страница** `/work/boards/<board>/inbox/` в рамке досок. Право — `can_read_inbox()`: кто работает с доской, плюс полный доступ.
  - Новые заявки: старые первыми; №, название, автор, подразделение, желаемая дата, когда.
  - Ниже — разобранные за 30 дней с итогом.
- **Заявка во «Входящих»** — тот же блок, что видит автор (`includes/request_summary.html`), и, пока заявка новая, три решения отдельными POST-маршрутами. Права проверяются до метода.
  - **«Принять»** (`accept_request()`):
    - форма: колонка (по умолчанию из настройки), исполнители (разбирающие, иначе владелец), срок (желаемая дата, иначе `intake_due_days` рабочих дней), название и описание — можно поправить;
    - карточка создаётся телом `create_card()` (`_place_new_card()`: закрепления, `BOARD_TASK_ASSIGNED`, подписчики колонки) с полями заявки;
    - первое сообщение чата — «Заявка от <автор>: <описание>», от имени принявшего;
    - запись `CREATED` с `request_id`, в «Логе» — «…создана из заявки №N в колонке …»;
    - после принятия открывается «Чат» новой карточки.
  - **«Отклонить»** — общее окно с обязательной причиной.
  - **«Отметить дублем»** — код карточки этой доски.
  - Повтор любого решения — «Заявку уже разобрали.», по отозванной — «Автор отозвал заявку.»
- **Счётчик «Входящие (N)»** — я выбрал **блок вкладок**:
  - он живой, а шапка — нет;
  - пункт стоит в конце вкладок, оранжевый при N > 0;
  - показывается тому, кто работает с доской, пока приём включён или есть ждущие заявки;
  - `request_changed` → доска перезапрашивает фрагмент → блок вкладок заменяется по отпечатку. Проверено в браузере без перезагрузки.

## 5. Решения, которых не было в задании

- **`/work/` — одно подключение `boards.urls`**: вложенные списки `boards/` и `requests/`. Два `include()` с одним пространством имён дали бы предупреждение проверки `urls.W005`; адреса досок не изменились.
- **Отдельный модуль `boards/request_views.py`**, чтобы не раздувать `views.py`; вспомогательные функции он берёт из `views.py`.
- **Принятие — одно событие `request_changed` с id новой карточки**, без отдельного `card_created`: клиент перезапрашивает фрагмент на любое `board.updated`.
- **Первое сообщение чата пишется напрямую**, а не через `post_card_comment()`: иначе люди карточки получили бы ещё и `BOARD_CARD_COMMENT`, хотя о карточке им только что сообщили назначением.
- **Значения полей заявки, которые больше не применимы** (поле убрали в архив или удалили, вариант списка убрали в архив), при принятии пропускаются, а не блокируют карточку.
- **Архив доски отклоняется**, пока есть новые заявки: иначе автор ждал бы ответа, который не может прийти.
- **«Входящие (N)» видны и при выключенном приёме**, если остались неразобранные заявки.
- **Отозвать можно и на архивной доске** — заявка там никого не ждёт.
- **Страница заявки для читающего «Входящие»** перенаправляет туда: из уведомления разбирающий попадает сразу к кнопкам.
- **Ревизия `boards`** получила шестой агрегат (заявки: число и `max(updated_at)`) — страховка на случай потерянного события. Бюджет запросов синхронизации 19 → 20 для пользователя с досками.
- **Число запросов страницы поддоски** — +2: число «Входящих» (только для работающего с доской) и ленивое `EXISTS` пункта меню «Заявки» (на каждой полной странице). Константы в четырёх тестах обновлены с пояснением.

## 6. Отклонения от задания

- **«Подразделение автора»** берётся из профиля как есть. Если у автора нет подразделения, выводится «—». Новой логики нет.
- **В ограничении «у `NEW` нет решения»** проверяются `decided_by`, `decided_at` и пустой `decision_comment`. У `WITHDRAWN` есть «кто и когда» (автор) — я посчитал отзыв решением автора.
- **«Отклонить» работает через общее окно** (JavaScript), как «Отменить карточку». Без JavaScript отклонить нельзя — так же устроены все действия с обязательным комментарием в проекте.
- Других отклонений нет. Пункты «не делать» соблюдены: файлов в заявке нет, публичной формы нет, распределения «по очереди» нет, заявки письмом нет.

## 8. Известные проблемы, риски, сомнения

- **Откат `notifications.0017` требует сначала удалить уведомления `REQUEST`** (описано в `docs/deployment.md`). Автоматически миграция этого не делает: удалять живые уведомления в миграции правило `AGENTS.md` запрещает.
- **Название заявки не попадает в уведомления** по правилу карточек — разбирающий видит «Заявка №N» и открывает её, чтобы понять суть. Если владелец захочет название в колокольчике, это изменение правила и для карточек.
- **Автор не может написать в чат карточки**, если он не участник доски: уточнения — через разбирающего. Комментарии к заявке до принятия не делались (их нет в задании).
- **Страницы «Заявки», «Входящие» и страница заявки не живые**: статус меняется после перехода или обновления. Живой только счётчик на доске.
- **Пункт меню «Заявки» добавляет одно `EXISTS` на каждой полной странице** (ленивый, во фрагменты не попадает).
- **Число запросов страницы с открытой карточкой — 45–46** (ревью этапа 23 уже предлагало поискать повторы). Остаётся на отдельный этап.
