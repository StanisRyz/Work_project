## 2. Что сделано

### §1. Модель

- **`BoardCardFile`** (`boards.0018_chat_files`): `card` и `comment` (PROTECT, `related_name='files'` у обоих), `uploaded_by` (PROTECT), `file` — `boards/files/<card_id>/<uuid>.<ext>` (`board_card_file_upload_to()`, расширение — через `ecosystem.attachments.attachment_extension()`, имени из браузера в пути нет), `original_name` (255), `size`, `content_type`, `created_at`, `deleted_at`/`deleted_by` (null). Индекс `(card, created_at)`. Свойства `is_image`, `extension`.
- `MAX_FILES_PER_MESSAGE = 10`, `PREVIEW_IMAGE_TYPES` (`.png/.jpg/.jpeg/.webp` → тип) — в `boards/models.py`.
- `BoardCardComment.text` — `blank=True` (только для Python; схема не меняется): пустой текст допустим, если есть файл. Правило — в сервисе.

### §2. Сервисы

- **`post_card_comment(..., files=…)`**:
  - право прежнее (`can_comment_card()` после блокировок доска → карточка);
  - `_clean_message_files()`: не больше 10, каждый файл — общей политикой `validate_attachment_upload()` (тип и размер); отказ — `BoardError` «Файл «x.exe»: Недопустимый тип файла.» до любой записи — ни строк, ни файлов на диске;
  - пустое сообщение без файлов — «Напишите сообщение или прикрепите файл.»;
  - файлы пишутся на диск до строк; весь `atomic()` обёрнут в `try/except`: при любом сбое (в том числе в уведомлениях) записанные файлы удаляются (`_remove_stored_file()`), затем ошибка идёт дальше — как в `add_task_attachment()`;
  - упоминания, уведомления (`BOARD_CARD_COMMENT`/`BOARD_CARD_MENTION`) и `board.updated(comment_added)` — по одному на сообщение, как раньше; текст уведомления сообщения не называет (и имени файла тоже — тест);
  - в журнал `board.comment_posted` добавлены `file_count` и `size_bytes`, имён нет.
- **`delete_card_file(file, *, actor)`**: блокировки доска → карточка → строка файла; архивная доска — отказ первым; право — новое `permissions.can_delete_card_file()` (загрузивший, пока работает на доске — т. е. активный участник, — или `is_act_admin()`); ставит `deleted_at`/`deleted_by`, `file` очищает, файл с диска удаляется `on_commit`; сдвигает `updated_at` карточки (страховка ревизии `boards`); одно `board.updated(file_deleted)`. Повтор — `False`, ничего не пишет и не публикует.
- **`file_deleted`** добавлен в `realtime.events.BOARD_CHANGES` (контрактный тест обновлён).
- **Журнал** событий о файлах не пишет: `selectors.card_log(card, attachments, card_files)` читает и вложения задачи, и файлы «Чата»: «Добавлен файл «X»», удалённый — «… (удалён)».

### §3. Выдача

- `boards:file_download` (`/<board>/cards/<card>/files/<file>/`) и `boards:file_preview` (`…/preview/`): строка ищется в рамках карточки и доски из адреса; право — `can_view_board()`; отказ, файл чужой карточки, удалённый и отсутствующий на диске — одинаковый 404. Журнал — `ecosystem.attachments` (`board.file_downloaded`/`board.file_access_denied`/`board.file_storage_failed`), только идентификаторы и размер.
- Превью — только картинки из `PREVIEW_IMAGE_TYPES`, тип из расширения (сохранённый `content_type` не читается — тест кладёт `text/html` и получает `image/png`), `inline`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`; не картинка — 404.
- `boards:file_delete` (POST): нечитатель — 404, без права удалить — 403 (до метода), GET ничего не меняет; `?chat=files` возвращает в «Только файлы».
- `AGENTS.md`, «Attachments are protected media» — добавлены файлы доски.

### §4. Чат

- **Форма** (`multipart/form-data`, тот же `boards:card_comment`): метка «📎 Файлы» с `input type=file name=files multiple`; без JavaScript это обычное поле выбора. `required` у текста снят (можно отправить одни файлы — проверяет сервер).
- **`static/js/board_chat_files.js`** (делегированный, инициализатор `qualityFragments`, ничего не проверяет): выбор через «📎» добавляется к уже выбранному; файлы, брошенные на вкладку «Чат» (она обводится пунктиром); вставка картинки из буфера → `скриншот-ГГГГ-ММ-ДД-ЧЧММСС.png` (если в буфере есть и текст — вставляется текст); каждый файл — плашка с именем, размером и «×». Выбор пишется в то же поле формы через `DataTransfer`; браузер без него остаётся с обычным полем. Выбранный файл помечает форму несохранённой (`qualityUnsavedGuard.markDirty()`).
- **Отказ** — панель с текстом и сообщением плюс «Выберите файлы заново.» (только если файлы были).
- **Сообщение**: картинки — миниатюры (`boards:file_preview`, до 240×160, щелчок — полный размер в новой вкладке); остальные — строка: значок по типу (PDF/DOC/XLS/TXT/IMG/FILE, цвета — токены доски), имя `.text-ellipsis` с `title`, размер, «Скачать»; «×» — для того, кто может, через общее окно (`data-confirm-form`, `includes/file_delete.html`); удалённый — серая строка «Файл удалён».
- **Старые вложения задачи** — в ленте по времени («Иван Иванов · дата · добавлен файл к задаче» и строка файла), скачивание `tasks:download_attachment`, удаление — `can_delete_task_attachment()` и `tasks:delete_attachment` (`list_query=tab=chat`). Ничего не переносится.
- **«Все сообщения | Только файлы · N»** над лентой (`&chat=files`): оба списка в одном живом блоке, видимый задаётся атрибутом `data-board-chat-mode` секции чата (вне блока) — сервер рисует, `board_drawer.js` переключает на месте, как вкладку (адрес и «Чат» в полосе вкладок следуют). «Только файлы» — все живые файлы карточки (чат + старые вложения), новые сверху: кто, когда, размер, «Скачать», «К сообщению» (якорь `#board-comment-N`/`#board-attachment-N`; если сообщение старше показанных 100 — ссылка на `comments=all`).
- **Живой блок** `[data-live-board-comments]` включает файлы и оба вида; отпечаток меняется при добавлении и удалении. Форма — вне блока: выбранные файлы при обновлении не теряются (тест Node). Число «Только файлы · N» ставит клиент вместе с блоком (`files_count`).
- **Плитка**: «📎 N» (живые файлы чата + вложения задачи) рядом с «💬 N» — аннотация `file_count_annotation()` в запросе колонок.

## 5. Решения, которых не было в задании

- **Подписчики — внизу «Описания»**, отдельным блоком под кнопками (задание разрешало отдельный блок). Альтернатива «в блок чек-листа» смешала бы два смысла и отложенную замену чек-листа.
- **Факты — третий контейнер охраняемой панели**: иначе чек-лист (вне охраны) нельзя поставить в разметке между описанием и фактами. Отпечаток — один на три контейнера; клиент заменяет все три вместе и считает «грязными» жесты в любом.
- **Режим чата — атрибут секции, оба списка в одном блоке**: переключение без запроса, отпечаток от режима не зависит, введённое в форме не теряется; без JavaScript — ссылки. «Чат» в полосе вкладок перенимает адрес текущего режима.
- **Файлы чата — один запрос на все файлы карточки**, а не prefetch по показанным сообщениям: тот же один запрос покрывает и ленту, и «Только файлы», и «Лог».
- **«×» только в ленте**, в «Только файлы» — «Скачать» и «К сообщению» (там нет контекста сообщения).
- **Вставка из буфера при наличии текста** оставляет текст: копирование ячейки Excel/Word кладёт в буфер и картинку — пользователь в этом случае хотел текст.
- **Имя скриншота** — по часам браузера пользователя (в контейнере — UTC, поэтому в результатах проверки `052720`, а время сообщения — 10:27 сервера).
- **Удалённый файл**: строка «Файл удалён» без имени; имя остаётся в «Логе» («… (удалён)»).
- **Фраза о старых вложениях** — «Иван Иванов · дата · добавлен файл к задаче», без родового глагола, как в «Логе» (в задании — «Иван Иванов добавил файл»).
- **`delete_card_file` для нечитателя — 404, для читателя без права — 403** (как отказ выдачи и как прочие маршруты доски соответственно).
- **Удаление файла сдвигает `updated_at` карточки** — ревизия `boards` в `/realtime/sync/` замечает его у пропустившего событие.

## 8. Известные проблемы, риски, сомнения

- **Файлы досок не попадают в «Документация» → «Вложения»** (`documents/references.py` не тронут — по заданию, п. 8). Нужен отдельный источник `AttachmentSource` на потом.
- **Старые вложения задачи в ленте видны по времени только в пределах показанных сообщений**: если вложение старше самого раннего из 100 последних сообщений, в ленте оно появится после «Показать ранние»; в «Только файлы» оно есть всегда.
- **Счётчик «📎 N» и миниатюры у читателей** обновляются вживую через `comment_added`/`file_deleted`; удаление *старого* вложения задачи даёт только `task.*` (как и раньше) — у тех, кто не исполнитель, оно видно через ревизию `boards` (если её сдвигает задача) или после перезагрузки.
- **Удаление с диска «по возможности»**: если удалить файл не удалось (ошибка ФС), строка-надгробие всё равно записана, в журнале — `board.file_cleanup_failed` (как у вложений задач).
- **Без `DataTransfer`** (очень старые браузеры) работает только обычное поле выбора: без плашек, перетаскивания и вставки.
- **Имя скриншота** берётся с часов компьютера пользователя.
- Кластер PostgreSQL — `/tmp/pg15`, порт 5432 (он был остановлен, перезапущен; пароль роли `quality` сменён на локальный, база `quality` пересоздана). Известные старые падения вне досок на PostgreSQL этим прогоном не затрагивались (наборы — как в задании).
