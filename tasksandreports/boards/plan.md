# Agile-доски: план

Простые канбан-доски для Отдела продаж и ПДО. Задачи с доски видны в
«Задачах»; задачи из других источников на доску не попадают.

## Архитектурные решения

1. **Карточка = `boards.BoardCard` + ровно одна `tasks.Task` с
   `source_type=BOARD`.** Карточка хранит место на доске (доска, колонка,
   позиция), заголовок и описание. Задача хранит работу: текст (собирается из
   заголовка и описания), исполнителей, срок, статус, выполнение, вложения.
2. **Четыре колонки задаются в коде** (`boards/columns.py`), без таблицы.
   «Сделать», «В работе», «На проверке» хранятся в `BoardCard.stage`.
   «Готово» не хранится: карточка там ⇔ её задача `COMPLETED`. Переоткрытие
   администратором возвращает карточку в её колонку, отменённая задача убирает
   карточку с доски.
3. **Перенос в «Готово» — это завершение задачи**: обязательный комментарий о
   результате, право — `can_complete_task()` (исполнитель или администратор).
4. **Одна карточка — одна общая задача**, без разбиения. Исполнители — только
   участники доски. Срок обязателен.
5. **Права** (`boards/permissions.py`): читают все; создают доски ПДО, Отдел
   продаж, руководитель, администратор (`BOARD_CREATOR_ROLES`); управляет
   доской владелец и администратор; с карточками работают участники и
   администратор.
6. **У доски есть подразделение** — оно становится `Task.department`.
   Организационная пометка, прав не даёт.
7. **Задача `BOARD` открывается на доске, а не как задача.** `tasks:detail`
   перенаправляет на доску с раскрытой карточкой
   (`/work/boards/<id>/?card=<pk>`); открытую карточку определяет сервер.
   Панель карточки умеет всё, что умела страница задачи (редактирование,
   перенос, завершение с комментарием, вложения, возврат в работу
   администратором), вызывая существующие сервисы и адреса задач.
   **Это не маршрутная задача**: `is_routing_task` её не включает, она
   завершается исполнителем и принимает вложения.
8. **Меню**: пункт первого уровня «Доски», адрес `/work/boards/`.
9. Досок может быть сколько угодно с первого этапа.
10. **Транспорт реального времени — SSE, не WebSocket.** Конфликты решаются на
    сервере (блокировки, версия карточки), а не транспортом; чат строится как
    комментарии — POST + событие + перезапрос. WebSocket — только отдельным
    архитектурным решением, если понадобится совместное редактирование.
11. **Полный доступ пока только у администратора.** `BOARD_ACCESS_ROLES` =
    {«Администратор»} плюс настоящий суперпользователь: видят все доски и
    создают их. Расширение — добавить роли в константу.
12. **Участник — любой сотрудник** (этап 10). Участник без полного доступа
    видит «Доски» в меню, но только свои доски, и задачи `BOARD` только
    своих досок. Подразделения у доски больше нет: в форме подразделение лишь
    фильтрует выбор сотрудника, а задача `BOARD` создаётся без
    подразделения.
13. **Доска → поддоски → колонки → карточки**, как в YouGile (этап 11).
    Участники, владелец, архив и права — на уровне доски; у поддоски свои
    колонки. Решения 2 и 3 меняются так:
    - колонки настраивает владелец или администратор;
    - у каждой поддоски одна завершающая колонка: карточка в ней ⇔ задача
      `COMPLETED`, бросок туда — завершение с результатом.
14. **Раскладка как в YouGile** (этап 12): список досок слева, вкладки
    поддосок сверху, реестра досок нет.
15. **Карточка — выдвижная панель с вкладками** «Описание», «Чат», «Файлы»,
    «Лог» (этап 13). Панель поверх колонок, а не вместо них. У карточки
    появляется журнал событий; завершение и возврат в работу идут через
    маршруты доски.

## Этапы

| # | Этап | Результат |
| --- | --- | --- |
| 1 | Фундамент | модели, тип задачи `BOARD`, сервисы, права, выборка доски; интерфейса нет |
| 2 | Интерфейс доски | меню, список досок, создание доски, участники, доска с 4 колонками, панель карточки `?card=` (просмотр, создание, редактирование, «Переместить в…»), карточка на главной |
| 3 | Карточка вместо страницы задачи | в панели: завершение с комментарием, вложения, возврат в работу; `tasks:detail` → доска; реестр задач: источник «Доска», ссылка, поиск; колокольчик и почта при назначении |
| 4 | Перетаскивание | мышь и тачскрин; бросок в «Готово» открывает окно с обязательным комментарием; откат при отказе сервера |
| 5 | Реальное время | доска обновляется у всех, кто её смотрит |
| 6 | Жизненный цикл | отмена карточки, архив доски, фильтры на доске, версия карточки против молчаливой перезаписи |
| 7 | Обсуждение в карточке | сообщения в панели карточки, живое появление отдельным блоком, колокольчик; уведомление об отмене карточки |
| 8 | Доводка перед пилотом (необязательный) | черновик «Выполнения» при отправке сообщения, лимит списка сообщений, проверка готовности к развёртыванию, инструкция для пилота |
| 9 | Допуск только администратору | одно правило `can_use_boards()` поверх всех прав, скрытые меню, главная и задачи `BOARD` для остальных |
| 10 | Участники и форма доски | участник — любой сотрудник, чтение по участию, форма «Название + Участники» с выбором «подразделение → сотрудник», доска без подразделения |
| 11 | Поддоски и колонки | модели `SubBoard`/`BoardColumn`, миграция данных, управление поддосками и колонками, перенос по id колонки |
| 12 | Раскладка YouGile | список досок слева, без реестра, шапка доски, вкладки и панель фильтров |
| 13 | Карточка с вкладками | выдвижная панель: Описание / Чат / Файлы / Лог, журнал событий карточки |

Этапы 2 и 3 поменяны местами относительно первой версии плана: связь с
«Задачами» ведёт на доску, поэтому сначала нужна сама доска.

## Принятые ограничения (к пилоту)

- Вложение, добавленное другим, не появляется в открытой панели вживую.
- Завершение со страницы задачи видно читателям доски с задержкой до
  `REALTIME_LIVE_SYNC_SECONDS`.
- Шапка доски (число участников) не обновляется вживую.
- Жесты на реальных iOS/Android проверялись только эмуляцией — проверить на устройствах в начале пилота.
- Поиск по кириллице без учёта регистра — только на PostgreSQL (как во всём проекте).
- Без JavaScript недописанное «Выполнение» не переносится при отправке сообщения.
- После своего сообщения панель снова показывает последние 100 (`comments=all` сбрасывается).
