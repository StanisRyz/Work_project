## Подзадачи

### Как сделано у других

**Битрикс24**
- У подзадачи только **одна** родительская задача.
- Подзадачу создают двумя способами: «Подзадачи» в родителе или «Родительская
  задача» в самой подзадаче.
- Подзадачу можно **отвязать** и сделать самостоятельной задачей.
- Есть опция «Автоматически завершать задачу при завершении подзадач и
  наоборот»: родитель закрывается, когда выполнены все подзадачи.
  Если завершить родителя, Битрикс24 завершит и все его подзадачи.
- В чек-листе: подпункты, ответственные за пункт, файлы к пункту.
- Источники: https://helpdesk.bitrix24.ru/open/27497372/,
  https://helpdesk.bitrix24.ru/open/17750248/,
  https://helpdesk.bitrix24.ru/open/27493452/,
  https://helpdesk.bitrix24.ru/open/17958164/

**ПланФикс**
- Вложенность почти не ограничена.
- Подзадачи видны:
  - на отдельной вкладке карточки;
  - по желанию — прямо в чек-листе родителя;
  - деревом в фильтрах.
- «Сроки выполнения подзадачи не могут быть позднее сроков выполнения
  надзадачи».
- В шаблоне задачи можно задать шаблон её подзадач.
- Есть режим «отдельная подзадача каждому исполнителю».
- Источник: https://planfix.ru/help/Подзадачи
- Строки табличных данных («аналитик»: например, позиции заказа) умеют
  **автоматически порождать задачи** — https://planfix.ru/help/Аналитика

**Яндекс Трекер**
- Подзадача — один из типов связи наряду с «Связанная», «Блокирующая —
  Зависимая», «Дублирующая», «Эпик», «Оригинал — Копия». Число связей не
  ограничено.
- Создаётся через «Действия → Добавить подзадачу».
- **Пункт чек-листа может иметь исполнителя и дедлайн**. Пункт можно
  превратить в подзадачу командой «Сделать подзадачей».
- Закрытие родителя после закрытия всех подзадач — не встроенная функция, а
  типовой пример триггера.
- Источники: https://yandex.ru/support/tracker/ru/user/ticket-links,
  https://yandex.ru/support/tracker/ru/user/checklist,
  https://yandex.ru/support/tracker/ru/manager/trigger-examples

**Pyrus**
- При создании подзадачи есть «Copy files from parent task».
- Типичный случай: задача обсуждается с клиентом, а подзадача — внутренняя.
- Источник: https://pyrus.com/en/help/tasks/files

**Kaiten** (производство)
- Заказ — родительская карточка, изделия — дочерние.
- Источник: https://kaiten.ru/blog/kaiten-for-production/ (2023, обновлено
  в январе 2026)

### Что из этого взять (к решению 21 плана)

1. **Только один уровень и один родитель.**
   - Подзадача подзадачи для запуска заказа не нужна. У Битрикс24 тоже
     один родитель.
   - Нужна кнопка «Отвязать — сделать отдельной карточкой». Она переносит
     подзадачу в первую рабочую колонку той же поддоски.
2. **Срок подзадачи — не позже срока родителя.** Так в ПланФиксе. Вариант
   мягче: предупреждение при сохранении. И подсветка на вкладке, если
   родителю сдвинули срок раньше подзадач.
3. **Пункт чек-листа → подзадача** (как «Сделать подзадачей» в Трекере).
   - Начали со списка шагов, один шаг вырос в работу другого человека — без
     перепечатывания.
   - Пункт удаляется, подзадача получает его текст. В журнале обеих
     карточек — запись.
4. **«Разбить по исполнителям»** при создании подзадачи (как в ПланФиксе).
   - У нас этот механизм уже есть у актов, протоколов и СМК
     (`split_for_assignees`).
   - Для подзадач он даёт по одной карточке на человека. Пример: «запросить
     у каждого цеха срок».
5. **Автозавершение родителя — опция, по умолчанию выключена.** По
   умолчанию оставить наше «предупредить при завершении». Дополнительно,
   когда закрыта последняя подзадача, предложить автору и исполнителям
   родителя «Все подзадачи выполнены — завершить заказ?» (колокольчик).
   Молча закрывать заказ на заводе опасно: остаются отгрузка и документы.
6. **Копировать файлы родителя в подзадачу** (Pyrus). Флажок при создании,
   например чертёж или спецификация — для цеха. Файлы копируются ссылкой,
   файл на диске не дублируется.
7. **Подзадачи из строк позиций заказа** (ПланФикс). См. строку 7 таблицы:
   имеет смысл, только когда появятся позиции заказа.
8. **Не путать подзадачу и «блокирует / зависит».** Трекер держит их
   отдельными типами связи. «Ждём снабжение» — это связь между карточками
   разных досок, а не подзадача (строка 4 таблицы).

## Файлы в комментариях

### Как сделано у других

**Битрикс24, «новые задачи» (2025–2026)**
- Обсуждение ведётся в чате.
- «Файлы, отправленные в чат задачи, сохраняются только в переписке. В блок
  «Файлы» попадают только документы, загруженные напрямую в карточку
  задачи».
- «Удалить файл может только сотрудник, который его загрузил».
- Сообщение чата можно **отметить как результат** задачи (блок «Требуется
  результат»).
- Изображения прикрепляются только отдельными файлами.
- Источник: https://helpdesk.bitrix24.ru/open/27344976/
- На маркетплейсе Битрикс24 появились приложения, которые собирают файлы из
  комментариев в поле карточки со ссылкой на комментарий. Значит, разнос
  файлов по ленте неудобен на практике:
  https://www.bitrix24.ru/apps/app/pavluk_online.files_from_comments/

**Pyrus**
- Файл из комментария виден и в ленте, и в разделе «Files» боковой панели.
- Есть версии одного документа: в ленте — уведомление со ссылкой на
  последнюю версию.
- Встроенный просмотрщик: PDF, офисные файлы, картинки, видео.
- Вставка скриншота через Ctrl+V.
- До 2 ГБ на файл.
- Источник: https://pyrus.com/en/help/tasks/files

**ПланФикс**
- Файл прикрепляется к комментарию и попадает в панель «Документы» задачи.
- При прикреплении можно **уведомить выбранных людей**.
- При загрузке файла с тем же именем есть выбор: новая версия,
  переименовать или взять ранее загруженный.
- Загрузка начинается сразу, до сохранения комментария.
- Источник: https://planfix.com/help/How_to_attach_files_to_a_task%3F

**Яндекс Трекер**
- Файлы прикрепляются к описанию или к комментарию. Мобильное приложение
  собирает их вместе в разделе «Файлы».
- Ограничение — 128 МБ на файл.
- Источники: https://yandex.ru/support/tracker/ru/user/attach-file,
  https://yandex.ru/support/tracker/ru/mobile/attach-file.md

### Что из этого взять (к решению 20 плана)

1. **Сводный список файлов карточки остаётся, хотя вкладки нет.**
   - Это главный урок Битрикс24: файлы только в ленте — и через месяц
     спецификацию не найти.
   - Вариант: «Файлы (N)» — переключатель «только сообщения с файлами» в
     «Чате» или строка-ссылка на «Описании».
   - Каждый файл ведёт к своему сообщению.
   - Источник один — сообщения чата плюс прежние вложения задачи.
2. **Сообщение с файлом → «Результат».**
   - В окне «Завершить» можно выбрать сообщение чата (с файлом) как
     результат, вместо перепечатывания текста. Это как в Битрикс24.
   - `Task.execution_comment` по-прежнему пишет только `complete_task()`.
     Сообщение лишь подставляет текст и ссылку.
3. **Версия по совпадению имени** (ПланФикс, Pyrus).
   - «Спецификация.xlsx» второй раз — это «версия 2», а не второй файл.
     Старая версия видна по ссылке.
   - Для ОП/ПДО это частый случай: заказ уточнили.
4. **Вставка скриншота из буфера (Ctrl+V)** в поле сообщения (Pyrus). Цеху и
   ОТК проще сфотографировать или вырезать фрагмент чертежа.
5. **Удаляет файл автор сообщения или администратор** — как в Битрикс24 и как
   наше правило для вложений актов. Удаление — с записью в «Лог».
6. **Просмотр картинок и PDF без скачивания.** У «Документации» уже есть
   безопасный просмотр (`documents/preview.py`, `INLINE_TYPES`, sandbox CSP).
   Его стоит переиспользовать, а не писать второй.
