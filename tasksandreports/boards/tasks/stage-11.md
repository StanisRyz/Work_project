# Agile-доски, этап 11: поддоски и настраиваемые колонки

Работа — прямо в `main` (см. `tasksandreports/README.md`). Начинать после
приёмки этапа 10.

## Зачем
Владелец хочет формат YouGile:
- внутри доски — несколько **поддосок** (вкладки сверху);
- у каждой поддоски — **свои колонки** с любыми названиями.

Этот этап меняет модель и даёт рабочие элементы управления. Рамку страницы
(доски слева, без реестра) делает этап 12, панель карточки — этап 13. Пиши
элементы этого этапа сразу начисто: этап 12 меняет вокруг них раскладку, но
не их самих.

Прочитай `plan.md` (решения 13–14), `feedback/2026-10-06/` (фото YouGile) и
раздел досок в `AGENTS.md` целиком.

## 1. Модель
- **`SubBoard`** («поддоска»):
  - `board` (FK, PROTECT, `related_name='sub_boards'`);
  - `name` (до 100);
  - `position`;
  - `created_by`;
  - `created_at`, `updated_at`;
  - уникальность `(board, name)`.
- **`BoardColumn`**:
  - `sub_board` (FK, PROTECT, `related_name='columns'`);
  - `name` (до 60);
  - `position`;
  - `is_done` (bool);
  - `created_at`, `updated_at`;
  - частичный unique «ровно одна `is_done` на поддоску».
- **`BoardCard`**:
  - `sub_board` (FK, PROTECT) — после миграции данных обязателен;
  - `column` (FK на `BoardColumn`, `SET_NULL`, `null=True`) — всегда
    **рабочая** колонка (не `is_done`). `position` упорядочивает карточки
    внутри колонки;
  - `board` остаётся: на нём держатся права, блокировки и события. Его
    совпадение с `sub_board.board` проверяют `clean()` и сервисы.
- **Миграции** — по правилу `AGENTS.md` (сначала добавить, потом данные,
  потом ужесточить):
  1. Новые модели и nullable-поля.
  2. Данные: каждой доске — поддоска «Основная» с колонками «Сделать»,
     «В работе», «На проверке», «Готово» (`is_done`). Карточки:
     `sub_board` = «Основная», `column` по старому `stage`, `position`
     сохраняется. Обратная операция восстанавливает `stage` по позиции
     колонки: первая → `TODO`, вторая → `IN_PROGRESS`, остальные и NULL →
     `REVIEW`.
  3. `sub_board` NOT NULL.
  4. Удалить `stage`.
- `boards/columns.py` больше не описывает колонки: он хранит только
  `DEFAULT_COLUMNS` для новой поддоски и `card_column()`:
  - `COMPLETED` → завершающая колонка поддоски;
  - `CANCELLED` → ни одной;
  - иначе → `card.column`, а если NULL — первая рабочая колонка поддоски.

  Возврат в работу кладёт карточку туда же.

## 2. Сервисы (`boards/services.py` — единственный писатель)
Порядок блокировок не меняется: каждая запись блокирует сначала `Board`.
Структурные изменения больше ничего не блокируют — блокировки доски
достаточно. Отказы — `BoardError`. Каждое успешное изменение — одно
`board.updated` с новым кодом `structure_changed` (`BOARD_CHANGES`, контракт
и тесты события).

- `create_board()` создаёт и поддоску «Основная» с `DEFAULT_COLUMNS`.
- Поддоски (право — `can_manage_board`):
  - `create_sub_board(board, name)` — с колонками по умолчанию, в конец;
  - `rename_sub_board`;
  - `move_sub_board(…, direction)` — влево или вправо;
  - `delete_sub_board` — только пустую (ни одной карточки, даже отменённой:
    карточки `PROTECT`) и не последнюю.
- Колонки (право — `can_manage_board`):
  - `create_column(sub_board, name)` — рабочая, перед завершающей;
  - `rename_column` — в том числе завершающей;
  - `move_column(…, direction)` — только рабочие и только среди рабочих;
    завершающая всегда последняя;
  - `delete_column` — только рабочую, только если в ней нет **открытых**
    карточек (задача `IN_PROGRESS`) и рабочих колонок останется хотя бы
    одна. У закрытых карточек `column` становится NULL.
  - Не больше 15 колонок на поддоску. Названия обрезаются, пустое
    отклоняется.
- Карточки:
  - `create_card(sub_board, column, …)` — колонка рабочая и из этой
    поддоски;
  - `move_card(card, column, before_card_id)` — то же правило, внутри
    поддоски карточки;
  - перенос между поддосками — вне рамок.
  - Бросок в завершающую колонку — по-прежнему завершение через окно с
    результатом.
- Фильтры и счётчики:
  - `parse_board_filters` и `column_counts` работают по поддоске;
  - счётчики — по id колонки, завершающая — под своим id.

## 3. Адреса и страница
- `/work/boards/<board>/` → перенаправление на первую поддоску.
- `/work/boards/<board>/<sub_board>/` — страница поддоски. Те же `?card=`,
  `&edit=1`, фильтры; создание — `?new=<column_id>`.
- Маршруты карточки остаются по `board` + `card`. После POST — на поддоску
  карточки с фильтром.
- `tasks.presentation.board_card_url()` ведёт на поддоску карточки.
  `tasks` по-прежнему не импортирует модели `boards`: id поддоски читается
  через `Task.board_card`.
- Фрагмент `boards:fragment` — по поддоске.
- Элементы управления (у кого `can_manage`; без JavaScript — обычные формы,
  с ним — те же формы в общем модальном окне или во всплывающем меню):
  - **Вкладки поддосок** над колонками: ссылки, активная выделена, «+»
    создаёт новую. У активной — меню «Переименовать / ← / → / Удалить».
  - **Шапка колонки**: название, счётчик, меню «⋯» с «Переименовать / ← / → /
    Удалить» (у завершающей — только «Переименовать»).
  - Справа от колонок — «+ Колонка».
  - Удаление — через общее окно подтверждения.
- Перетаскивание (`board_dnd.js`): колонки различаются по
  `data-column-id`, запрос несёт `column_id`. Остальное поведение и JSON
  (`counts` по id колонок) не меняется.
- Перетаскивание самих колонок и поддосок — вне рамок; порядок меняют ← →.

## 4. Реальное время и синхронизация
- `structure_changed` обновляет колонки и вкладки. Вкладки сделай частью
  живого блока колонок или отдельным блоком только для чтения.
- Ревизия `boards` учитывает поддоски и колонки: число и максимальный
  `updated_at`.
- Удалённая или переименованная колонка, в которую пользователь сейчас
  тащит карточку: перенос отклоняется сервером, плитка возвращается на место.

## 7. Тесты
- Миграция данных:
  - доска с карточками во всех трёх рабочих колонках, выполненной и
    отменённой карточкой переносится без потерь, позиции сохраняются;
  - откат на шаг возвращает `stage`.

  Тест через `MigrationExecutor` или проверка на PostgreSQL с выводом в
  отчёте.
- Сервисы:
  - все операции поддосок и колонок с правами (владелец, администратор —
    да; участник — нет; архивная доска — нет);
  - каждое правило удаления;
  - лимит колонок;
  - одно событие на успех, ни одного на отказ.
- `card_column()`:
  - открытая, выполненная и отменённая карточки;
  - колонка NULL;
  - возврат в работу после удаления колонки.
- Перенос:
  - в чужую поддоску и в завершающую колонку через `card_move` — 400;
  - JSON-счётчики по id.
- Страница и фрагмент равны для поддоски.
- Число запросов не растёт с числом колонок и карточек.
- Все прежние тесты досок адаптированы к поддоскам, ни один проверяемый
  смысл не потерян.
