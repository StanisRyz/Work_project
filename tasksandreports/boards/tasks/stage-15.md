## 1. Модель
- **`BoardField`** — поле карточек доски, общее для всех её поддосок:
  - `board` (FK, PROTECT, `related_name='fields'`);
  - `name` (до 60);
  - `kind`: `TEXT` / `NUMBER` / `DATE` / `SELECT`;
  - `position`;
  - `show_on_tile` (bool, по умолчанию `True`);
  - `is_archived` (bool);
  - `created_at`, `updated_at`.

  Не больше `MAX_FIELDS = 20` живых полей на доску. Имя уникально среди
  полей доски без учёта регистра — проверяет сервис (через `casefold`, как у
  поддосок).
- **`BoardFieldOption`** — вариант поля-списка:
  - `field` (FK, CASCADE, `related_name='options'`);
  - `label` (до 60);
  - `color` — код из закрытого набора цветов (`gray`, `blue`, `green`,
    `yellow`, `orange`, `red`, `purple`, `teal`);
  - `position`, `is_archived`.

  Не больше 30 живых вариантов.
- **`BoardCardFieldValue`** — значение поля у карточки:
  - `card` (FK, CASCADE);
  - `field` (FK, PROTECT);
  - `value_text` (до 500, пусто — NULL);
  - `value_number` (`DecimalField(18, 4)`);
  - `value_date`;
  - `option` (FK, PROTECT).

  Правила целостности:
  - уникальность `(card, field)`;
  - check-ограничение «ровно одна колонка значения заполнена»;
  - соответствие вида поля и колонки проверяют `clean()` и сервис.

  Пустое значение — **нет строки**.
- **Ничего не удаляется насовсем, если на это ссылаются значения:**
  - поле и вариант с хотя бы одним значением только **архивируются**: не
    предлагаются при вводе, не видны на плитке, но значение сохраняется и
    показывается на «Описании» с пометкой «(в архиве)»;
  - удалить можно только неиспользованные;
  - у поля, у которого есть значения, нельзя менять `kind`.

  `card` — CASCADE, потому что карточки не удаляются: каскад только для
  полноты схемы.

## 2. Сервисы (`boards/services.py`, единственный писатель)
- **Настройка полей** (право `can_manage_board`, одна блокировка доски,
  архивная доска — отказ, `BoardError`):
  - `create_field`, `update_field` (имя, `show_on_tile`; вид — только пока
    значений нет), `move_field` (← →), `archive_field` / `restore_field`,
    `delete_field` (только без значений);
  - то же для вариантов: `create_option`, `update_option` (подпись, цвет),
    `move_option`, `archive_option` / `restore_option`, `delete_option`.

  Каждое успешное изменение — одно `board.updated(structure_changed)`. «То
  же самое» не пишет и не публикует ничего.
- **Значения:**
  - `create_card()` и `update_card()` принимают `field_values`
    (`{field_id: сырое значение}`);
  - сервис проверяет, что поле этой доски и живое, и разбирает значение по
    виду:
    - текст — обрезка, до 500;
    - число — `Decimal`, допускается запятая, не больше 14 знаков до
      запятой;
    - дата — ISO;
    - список — id живого варианта этого поля;
  - пустое значение удаляет строку;
  - ошибки — `BoardError` с названием поля;
  - архивное поле в `field_values` игнорируется: его значение не трогается,
    даже если форма его прислала.
- **Правка значений — часть `update_card()`:**
  - та же версия (`BoardCard.version` растёт);
  - то же событие `card_updated`;
  - запись журнала `EDITED`: `details.fields` получает `custom`,
    `details.custom_fields` — названия изменённых полей на момент правки.
    Текст: «Изменено: Номер заявки, Срок изг.»;
  - правка без изменений по-прежнему не пишет ничего.

## 3. Страница «Поля карточек»
- **Адрес:** `/work/boards/<board>/fields/`, в рамке `boards/layout.html`. В
  меню «⋯» доски — пункт «Поля карточек» (`can_manage_board`). Читать
  страницу может любой читатель доски, менять — только владелец или
  администратор: остальные видят список без форм.
- **Список полей по порядку:** имя, вид, «на плитке», число карточек со
  значением. Действия:
  - «Переименовать»;
  - вид (выбор, пока значений нет);
  - «Показывать на плитке»;
  - ← →;
  - «В архив» / «Вернуть»;
  - «Удалить» (только без значений, через общее окно подтверждения).
- **У поля-списка — варианты:**
  - цветная плашка с подписью;
  - переименование и смена цвета (выбор из восьми цветов);
  - ← →, архив и возврат, удаление.
- **«+ Поле»:** имя и вид; для списка — сразу несколько вариантов через
  строки (без JavaScript — по одному, как у участников).
- Всё работает обычными POST-формами без JavaScript. Отказ — сообщением на
  странице.

## 4. Карточка
- **Форма создания и правки** (`CardForm`): после стандартных полей —
  живые поля доски по порядку:
  - текст — однострочное поле;
  - число — `inputmode="decimal"`;
  - дата — `type="date"`;
  - список — `select` с пустым вариантом, у варианта цветной маркер в
    подписи.

  Значения, введённые до отказа, при отказе остаются в форме.
- **Вкладка «Описание»:** после стандартных фактов — значения полей по
  порядку полей. Пустые не показываются. Список — цветной плашкой, дата —
  `ДД.ММ.ГГГГ`, число — без хвостовых нулей и с пробелами между разрядами.
- **Плитка:** под заголовком — до 4 значений полей с `show_on_tile` (по
  порядку полей):
  - список — цветной плашкой;
  - остальные — «Имя: значение» мелко, `.text-ellipsis` с полным текстом в
    `title`.
- **Цвета** — восемь пар «фон / текст» как токены в `static/css/boards.css`
  (`--board-color-blue-bg` …), объявленные один раз. Плашки — по классу
  `board-chip--<цвет>`.
- **Число запросов** страницы и фрагмента **не растёт** с числом полей,
  вариантов и значений:
  - поля доски с вариантами — один запрос плюс prefetch;
  - значения всех карточек на странице — один запрос.

  Поправь тесты на постоянство. Для страницы с открытой карточкой назови в
  отчёте новое число.
- **Живое обновление:**
  - смена настроек полей — `structure_changed`;
  - значения — `card_updated`;
  - фрагмент равен странице;
  - отпечаток колонок двигается при смене значений, видимых на плитке, и
    при смене настроек.

## 8. Тесты
- **Модель и миграции:**
  - ограничения: уникальность, одна колонка значения;
  - миграции с нуля и откат на SQLite и PostgreSQL.
- **Настройка:**
  - каждая операция с полями и вариантами;
  - права: владелец и администратор — да; участник, посторонний, архивная
    доска — нет; маршруты — 403 до метода, GET ничего не меняет;
  - лимиты;
  - уникальность имени без учёта регистра;
  - запрет смены вида и удаления при наличии значений;
  - архив и возврат;
  - одно событие на успех, ни одного на отказ или «то же самое».
- **Значения:**
  - разбор каждого вида, в том числе запятая в числе, неверная дата,
    чужой вариант, вариант из архива;
  - пустое удаляет;
  - поле чужой доски — отказ;
  - архивное поле не трогается;
  - журнал с названиями;
  - версия;
  - правка без изменений ничего не пишет.
- **Показ:**
  - «Описание» и плитка, лимит 4, `show_on_tile`, архивное значение с
    пометкой;
  - фрагмент равен странице;
  - число запросов не растёт с полями, вариантами и значениями.

**Браузер** (Playwright, 1920×1080 и 1536×864, скриншоты в
`reports/stage-15/`):
1. страница «Поля карточек» с полями «Номер заявки» (текст), «Заказ
   покупателя» (текст), «Срок изготовления» (дата), «Приоритет» (список:
   Высокий/красный, Средний/жёлтый, Низкий/серый), «Стоп» (список: Да/красный);
2. карточка с этими значениями — форма, «Описание», плитка;
3. второй пользователь видит новые значения на плитке без перезагрузки;
4. архивное поле на «Описании».
