## 1. «Застой» становится «Нормативом этапа»
Решение 23 (`plan.md`). Два похожих порога у одной колонки путали бы.
Поэтому «Застой» (этап 17, календарные дни) превращается в норматив этапа в
**рабочих днях**.
- **Поле:**
  - `BoardColumn.stale_after_days` переименовать в `norm_working_days` —
    миграция `RenameField`, значения сохраняются как есть;
  - ограничение — то же: 1–365 или NULL, не у завершающей колонки.
- **Подписи в интерфейсе:** «Норматив этапа: N раб. дн.» (меню «⋯» колонки,
  шапка — «⏱ N р.д.»).
- **Сервис** `set_column_stale_days` → `set_column_norm()`.
  Маршрут переименуй, а старое имя маршрута не оставляй.
- **Счёт дней:**
  - новая функция `ecosystem.workdays.working_days_between(start, end)` —
    рабочих дней после `start` до `end` включительно, отрицательно, если
    `end` раньше. Одна функция, с тестами на выходные;
  - «в колонке N дн.» на плитке остаётся календарным: это просто возраст;
  - **светофор** считается в рабочих днях.

## 2. Светофор и план/факт
- **Плановая дата выхода из этапа:**
  `add_working_days(localdate(вошла в колонку), norm)`. «Вошла» — уже
  существующий `in_column_since()`.
- **Цвет открытой карточки в колонке с нормативом:**
  - зелёный — до плановой даты больше одного рабочего дня;
  - жёлтый — плановая дата сегодня или в следующий рабочий день;
  - красный — плановая дата прошла.

  Без норматива — без цвета.
- **Плитка:**
  - точка светофора и «план до 14.10» (подпись в `title`);
  - красная плитка — это прежняя подсветка «Застоя» (`board-tile--stale`
    переименуй по смыслу).
- **Фильтр «Застрявшие»** (`stale=1`) теперь значит «красные»: плановая дата
  прошла. Разбор и действие — прежние. Подпись «Просрочен этап».
- **Путь по этапам** на «Описании» — блок «Этапы»:
  - строка на каждую колонку, где карточка стояла: название колонки на
    момент события, вошла, плановый выход (если у колонки сейчас есть
    норматив), фактический выход, отклонение в рабочих днях;
  - строится из журнала: `CREATED`, `MOVED`, `REOPENED`, `COMPLETED`.
    Норматив берётся **текущий** — прежний не хранился, так и подпиши: «по
    текущему нормативу»;
  - живой блок только для чтения или часть уже существующего блока — без
    поднятия баннера;
  - запросов — не больше одного на панель.
- **«Таблица» и Excel:** столбцы «План выхода из этапа» и «Отклонение этапа,
  р.д.» (положительное — опоздание). Сортировка по отклонению — в белом
  списке.

## 3. Отчёт по этапам
На странице «Отклонения» (этап 21) — вторая вкладка «Этапы» (`?view=stages`):
- для каждой рабочей колонки поддоски — сколько карточек вышло из неё за
  период;
- среднее и максимальное время в этапе (рабочие дни);
- доля уложившихся в норматив (если он есть);
- сколько сейчас стоит с красным светофором.

Считается из журнала за период. Excel — та же таблица. Число запросов не
растёт с числом карточек: читай события периода одним запросом, считай в
Python.

## 4. Дайджест руководителю
- **Подписка `BoardDigestSubscription`:**
  - поля: `board`, `user` (PROTECT), `frequency` (`DAILY` / `WEEKLY`),
    `created_at`; уникальность `(board, user)`;
  - в меню «⋯» доски — «Дайджест на почту: ежедневно / еженедельно /
    выключен» (обычная форма, любой читатель доски, не на архивной);
  - удаление участника снимает подписку.
- **Команда `manage.py board_digest`** — раз в день, утром (`docs/deployment.md`
  рядом с прочими ежедневными):
  - `DAILY` — каждый рабочий день;
  - `WEEKLY` — по понедельникам;
  - идемпотентность: строка «отправлено за дату» (`last_sent_on` на
    подписке). Повторный запуск в тот же день ничего не шлёт.
- **Письмо — одно на человека,** все его подписанные доски по разделам:
  - просроченные карточки (код, название, срок, исполнители);
  - «просрочен этап» (код, колонка, на сколько р.д.);
  - заблокированные (этап 22);
  - переносы срока за период с причинами;
  - выполнено за период (число);
  - ссылки на доску и на «Таблицу» с нужным фильтром.

  Только карточки досок, которые человек ещё читает (`can_view_board()`).
- **Как отправляется:** как `send_welcome_email`, напрямую через настроенный
  backend.
  - Без `Notification`: дайджест — не бизнес-факт, а сводка.
  - Отказывается работать при `EMAIL_NOTIFICATIONS_ENABLED=false`.
  - Ошибки — через `sanitize_error()`.
  - В лог — только счётчики (отправлено, пропущено без адреса, ошибок).
  - Шаблон — `boards/email/digest.{txt,html}`, в стиле общих писем.
  - Опиши в `AGENTS.md`, почему дайджест не идёт через `Notification`.
- **Пустой дайджест** (по всем доскам ничего, кроме «выполнено: 0») не
  отправляется.

## 8. Тесты
- **`working_days_between`:** выходные, тот же день, отрицательный
  интервал.
- **Миграция переименования:** значения на месте, вперёд и назад.
- **Светофор:**
  - границы трёх цветов, включая пятницу → понедельник;
  - без норматива — без цвета;
  - фильтр `stale` по новому смыслу;
  - число запросов.
- **«Этапы»:**
  - путь по журналу, возврат в работу, перенос между поддосками;
  - отклонение.
- **Отчёт:** среднее, максимум, доля, период; посторонний — 403; Excel.
- **Дайджест:**
  - подписка и права;
  - `DAILY`/`WEEKLY` по дням;
  - идемпотентность;
  - пустой не шлётся;
  - чужая доска после исключения не попадает;
  - почта выключена — отказ;
  - письмо содержит разделы (`locmem` backend);
  - в логе нет адресов.

**Браузер** (Playwright, 1920×1080 и 1536×864, скриншоты в
`reports/stage-23/`):
1. норматив в меню колонки, светофор на плитках трёх цветов (сдвинь даты
   журнала в демо-данных);
2. блок «Этапы» на «Описании»;
3. вкладка отчёта «Этапы»;
4. подписка на дайджест; текст письма (`locmem` или файл), приложить в отчёт.
