# Agile-доски, этап 6: отмена карточки, архив доски, фильтры, защита от перезаписи

Работа — прямо в `main` (см. `tasksandreports/README.md`).

## Контекст
Прочитай `tasksandreports/boards/plan.md`, `reviews/stage-05.md`, затем
`AGENTS.md` целиком: раздел досок, отменённые задачи (`TaskStatus`,
`cancel_smk_action_tasks()`), полку СМК (`SmkSource.status` и
`archive_smk_source()` — образец архива), общий confirm-modal и правила
живых блоков.

Цель этапа — четыре вещи, которых не хватает для пилота:
1. ошибочную карточку можно отменить;
2. законченную доску можно убрать в архив и вернуть;
3. на доске можно отфильтровать свои и просроченные карточки и найти карточку
   по названию;
4. две одновременные правки одной карточки не затирают друг друга молча.

## 0. Поправка по этапу 5
См. `reviews/stage-05.md`, п. 1. Перенос открытой в панели карточки при
работающем real-time ничего не делает сверх обычного. Без real-time —
`location.replace(...)`, как сейчас. Тест в Node-обвязке и проверка в
браузере.

## 1. Отмена карточки
- `tasks.services.cancel_board_card_task(task, *, actor, reason)`:
  - только `BOARD` в `IN_PROGRESS`;
  - `CANCELLED`, `cancelled_at`/`cancelled_by`/`cancellation_reason`;
  - `completed_by` и `execution_comment` не трогаются;
  - `updated_at` в `update_fields`;
  - `emit_task_updated`;
  - пустая причина отклоняется.

  Он пишется по образцу `cancel_smk_action_tasks()`. Поправь в `AGENTS.md`
  фразу «Written only by `cancel_smk_action_tasks()`»: отменяют уже несколько
  писателей, каждый для своего источника. Перечисли их.
- `boards.services.cancel_card(card, *, actor, reason)`:
  - блокировки доска → карточка → задача, право после блокировок;
  - вызывает функцию выше;
  - публикует `board.updated` с новым кодом `card_cancelled` (добавь в
    `BOARD_CHANGES`, контракт и тесты).
- Право: `boards.permissions.can_cancel_card(user, card)` — автор карточки,
  владелец доски (пока он активный сотрудник) или `is_act_admin`. И только
  пока доска не в архиве. Исполнитель, не являющийся автором, отменить не
  может: он *завершает*.
- Интерфейс:
  - в панели открытой карточки кнопка «Отменить карточку» через общий
    confirm-modal с обязательной причиной
    (`data-confirm-comment="required"`, имя поля — как ждёт view);
  - POST на `boards:card_cancel`;
  - карточка исчезает с доски — это уже так по `card_column()`;
  - отменённая панель по `?card=` показывает причину, кто и когда (уже есть);
  - в «Задачах» отменённая задача попадает в «Архив» сама.
- Уведомлений нет: как и при отмене задач СМК, задача просто уходит из
  «Мои задачи». Если считаешь, что исполнителям нужно знать, — напиши в
  отчёте, не делай.

## 2. Архив доски
- `Board.status` (`ACTIVE`/`ARCHIVED`, по умолчанию `ACTIVE`), `archived_at`,
  `archived_by`. Миграция добавляет поля в существующую таблицу.
- `archive_board(board, *, actor)` и `restore_board(board, *, actor)` в
  `boards/services.py`:
  - право — `can_manage_board`, проверяется под блокировкой;
  - **архив отклоняется, пока на доске есть открытые карточки** («Сначала
    завершите или отмените открытые карточки: N»);
  - оба действия публикуют `board.updated` с кодом `board_archived` /
    `board_restored`.
- Архивная доска — только для чтения:
  - `can_work_on_board()` возвращает False;
  - `can_manage_board()` разрешает только «Вернуть из архива»;
  - добавление участников, создание, правка, перенос и отмена отклоняются
    сервисами — проверь каждый путь тестом;
  - страница доски открывается по тому же адресу с пометкой «В архиве».
- Реестр досок: вкладки «Мои», «Все», «Архив». «Мои» и «Все» — только
  активные.
- Кнопки «В архив» и «Вернуть из архива» в шапке доски, через общий
  confirm-modal без комментария.

## 3. Фильтры на доске
- GET-параметры:
  - `mine=1` — карточки, где я исполнитель;
  - `overdue=1` — срок прошёл, задача открыта;
  - `q` — подстрока в заголовке, без учёта регистра.

  Применяются в `build_board_state()` — один и тот же разбор для страницы и
  фрагмента. «Готово» фильтруется теми же правилами, кроме `overdue`, к
  выполненным он не применяется. Счётчики колонок показывают
  отфильтрованное число.
- Форма фильтров в шапке доски — `form[data-registry-filter]` (общий
  `registry_tools.js`: флажки применяются по `change`, поиск — после паузы).
  Сохранение в `localStorage` не нужно.
- Параметры фильтра сохраняются:
  - в ссылках плиток (`?card=` + фильтр);
  - в адресе фрагмента и в `data-board-page-url`;
  - в перенаправлениях после POST — если это сложно, хотя бы ссылка
    «Закрыть» панели и плитки.

  Опиши в отчёте, что сделал.
- Перетаскивание с включённым фильтром: `before_card_id` — следующая
  *видимая* карточка; сервис ставит относительно полной колонки. Проверь в
  браузере, что порядок не ломается.
- «Сбросить» — ссылка на доску без параметров фильтра.

## 4. Защита от молчаливой перезаписи
- `BoardCard.version` — `PositiveIntegerField(default=1)`. Растёт на 1 при
  каждой правке, которая что-то записала (`update_card()` со `stored=True`).
  Перенос и завершение версию не меняют: они не конфликтуют с правкой текста.
  Миграция добавляет поле в существующую таблицу.
- Форма правки несёт скрытое `version`. `update_card(..., expected_version)`
  под блокировкой сравнивает его с текущей версией. Если не совпало —
  `BoardError` «Карточку изменили, пока вы её редактировали. Ваши правки не
  сохранены: проверьте текущую версию и внесите их снова».
- Страница после такого отказа — панель правки с введёнными значениями и
  ошибкой. Плюс ссылка «Открыть текущую версию» (`?card=<pk>`) в новой вкладке
  (`target="_blank"`), чтобы введённое не потерялось.
- `expected_version=None` (вызов не из формы) — без проверки. Форма всегда
  передаёт версию.
- Тесты: две «вкладки» прочитали версию 1, первая сохранила (версия 2), вторая
  получает отказ, база содержит правку первой. Пустая правка версию не
  меняет. Перенос версию не меняет.

## 5. Тесты
- Отмена:
  - кто может и кто нет;
  - пустая причина;
  - отмена закрытой задачи;
  - архивная доска;
  - карточка ушла с колонок, задача в «Архиве» реестра;
  - `cancellation_reason` записан;
  - одно событие `board.updated(card_cancelled)` после коммита, при отказе —
    ничего;
  - ревизия `boards` сдвинулась.
- Архив:
  - отказ при открытых карточках;
  - успешный архив и возврат;
  - каждый мутирующий маршрут и сервис на архивной доске отклоняется (403 до
    метода там, где это право доски);
  - вкладки реестра.
- Фильтры:
  - каждый параметр и их сочетание;
  - счётчики;
  - фрагмент равен странице при том же фильтре (отпечаток);
  - параметры в ссылках плиток;
  - число запросов постоянно.
- Версия — см. п. 4.
- Браузер (Playwright, Redis, если можно, как на этапе 5):
  - отмена через окно с причиной;
  - архив и возврат;
  - фильтр «Мои» и поиск;
  - перетаскивание с фильтром;
  - две вкладки правят одну карточку — вторая получает отказ, текст на месте;
  - поправка §0.

  Скриншоты:
  - окно отмены;
  - архивная доска;
  - доска с фильтром;
  - отказ из-за версии.
