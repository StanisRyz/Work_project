## 1. Фильтр по полям доски
- **Параметры адреса** — по одному на поле доски, ключ от id поля:
  - список — `f_<id>=<id варианта>`, можно несколько (логическое «или»
    внутри поля); `f_<id>=none` — «не задано» (карточки без значения), можно
    вместе с вариантами;
  - дата — `f_<id>_from=ГГГГ-ММ-ДД` и/или `f_<id>_to=ГГГГ-ММ-ДД`, включительно;
  - число — `f_<id>_min` и/или `f_<id>_max`, включительно, разбор как у
    значения (запятая допускается);
  - текст — `f_<id>=<строка>`, вхождение без учёта регистра.

  Разные поля соединяются логическим «и», и со старыми `mine`/`overdue`/`q`
  тоже.
- **Разбор — один**, в `boards/selectors.py`: `parse_board_filters(params,
  fields)` (поля доски передаются — их уже читает `board_fields()`).
  `BoardFilters` получает фильтры полей. `is_active` и `query` их учитывают;
  `query` — в стабильном порядке (по позиции поля), чтобы адреса не
  дрожали.
- **Ошибочный ввод не ломает страницу:**
  - неизвестный id, поле чужой доски, архивное поле, чужой или неверный
    вариант, неверная дата или число — параметр **молча отбрасывается**:
    его нет в `query` и он не фильтрует;
  - никаких 400 и 500. Это удобство адреса, а не правило.
  - Архивный вариант живого поля — допустим в фильтре (карточки его ещё
    держат), но в форме фильтра не предлагается, если не выбран.
- **Где действует** — везде, где действуют `mine`/`q` сейчас:
  - колонки страницы и фрагмента;
  - завершающая колонка (как `mine` и `q`; `overdue` её по-прежнему не
    трогает);
  - `column_counts()` и JSON ответа перетаскивания;
  - `filter_query` во всех адресах, которые рисует страница (плитки, панель,
    формы, фрагмент, `data-board-page-url`), — переходы после POST остаются
    на отфильтрованной доске.
- **Запросы:** каждое поле фильтра — `Exists(...)` по `BoardCardFieldValue`
  (или `~Exists` для «не задано») в том же запросе задач. Число запросов
  страницы не растёт с числом активных фильтров и полей. Тест.
- **Панель карточки** по-прежнему находится, что бы ни говорил фильтр.

## 2. Поиск `q` по значениям
- Поиск доски `q` дополнительно находит карточку по **значению текстового
  поля** (вхождение без учёта регистра) — только живых полей, не архивных.
  Номер заявки «3-1579» находит карточку.
- Поиск реестра «Задачи» (по колонке «Источник» или общий, где уже ищут
  код карточки) и быстрый поиск в шапке находят задачу `BOARD` по значению
  текстового живого поля её карточки. Видимость не меняется: всё внутри
  существующих читаемых querysets, через `Exists`. Число запросов не растёт
  (тест).
- Одно место правила «что ищется по значениям» — функция в
  `boards/selectors.py` или `tasks/selectors.py` рядом с
  `board_card_code_filter()`; поиск доски и реестр зовут её, а не
  повторяют условие.

## 3. Интерфейс фильтра
- В строке фильтров под вкладками — кнопка «Поля» (`<details>`, работает без
  JavaScript), появляется только если у доски есть живые поля. Внутри — по
  строке на живое поле по порядку:
  - список — флажки вариантов (цветные плашки) и «не задано»;
  - дата — «с» и «по» (`type="date"`);
  - число — «от» и «до» (`inputmode="decimal"`);
  - текст — строка поиска.
- На кнопке — число активных фильтров полей: «Поля · 2».
- Под строкой фильтров, когда фильтры полей заданы, — плашки активных
  фильтров: «Приоритет: Высокий, Средний ×», «Срок изготовления: по
  30.11.2026 ×». Крестик — ссылка на тот же адрес без этого поля.
- Форма — тот же `form[data-registry-filter]` (`registry_tools.js`): флажок и
  выбор применяются сразу, текст и числа — после паузы. Без JavaScript —
  кнопка «Применить».
- «Сбросить» сбрасывает и фильтры полей, панель карточки остаётся открытой.
- Ширины — по содержимому и токенам, на 1536 и 1920 строка фильтров не
  ломается. Ниже 760 px — обычный поток.

## 4. Живое обновление
- Фрагмент несёт тот же фильтр (адрес фрагмента строится сервером). При
  смене значения карточка появляется или исчезает в отфильтрованных
  колонках у второго пользователя без перезагрузки.
- Поле удалили или убрали в архив, пока открыт отфильтрованный адрес:
  фрагмент отбрасывает такой фильтр, страница не падает. Адреса страницы
  берутся из ответа, как сейчас.

## 8. Тесты
- **Разбор:** каждый вид; несколько вариантов; «не задано»; границы
  включительно; запятая в числе; мусор, чужое поле, архивное поле, чужой
  вариант — отброшены; `query` стабилен и обратим (разбор `query` даёт тот
  же фильтр).
- **Применение:** страница, фрагмент и `column_counts()` дают одно и то же;
  завершающая колонка; сочетание с `mine`/`overdue`/`q`; JSON
  перетаскивания под фильтром; адреса несут фильтр; панель открыта при
  несовпадении.
- **Поиск:** доска, реестр «Задачи», быстрый поиск находят по номеру заявки;
  архивное поле — не находит; чужую доску — не находит.
- **Число запросов:** страница и фрагмент постоянны при 0, 1 и 5 активных
  фильтрах; поиск реестра и шапки постоянен.
- Страница = фрагмент с фильтрами полей.

**Браузер** (Playwright, 1920×1080 и 1536×864, скриншоты в
`reports/stage-16/`), на демо-данных этапа 15:
1. панель «Поля» открыта; выбран «Приоритет: Высокий» — остались нужные
   карточки, счётчики колонок верны, плашка фильтра видна;
2. «Срок изготовления» по дате и «Стоп: Да» вместе;
3. поиск «3-1579» находит карточку на доске, в «Задачах» и в шапке;
4. второй пользователь ставит карточке «Высокий» — у первого она появляется
   в отфильтрованной колонке без перезагрузки;
5. перетаскивание под фильтром.
