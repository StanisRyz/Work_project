# Agile-доски, этап 3 из 6: карточка вместо страницы задачи

Работа — прямо в `main` (см. `tasksandreports/README.md`). Этапы 1 и 2 уже в
`main`.

## Контекст
Прочитай `tasksandreports/boards/plan.md` (особенно решение 7),
`reviews/stage-02.md`, затем `AGENTS.md` целиком.

Цель этапа: задача `BOARD` живёт на доске. Пользователь из «Задач»,
уведомления или письма попадает на доску с открытой панелью карточки, и в
панели есть всё, что давала страница задачи:
- завершение с комментарием;
- вложения;
- результат выполнения;
- «Вернуть в работу» для администратора.

Плюс оформление источника в реестре задач и уведомление о назначении.

Главное правило этапа: **`BOARD` — не маршрутная задача.** `is_routing_task`
её не включает. Она завершается исполнителем через `complete_task()`,
принимает вложения, её переоткрывает администратор. Меняется только то, *где*
она показывается. `can_complete_task()`, `complete_task()`, `reopen_task()` и
сервисы вложений не трогать.

## 1. Где задача `BOARD` открывается
- Адрес карточки строит одна функция в `tasks/presentation.py`, например
  `board_card_url(task)` → `reverse('boards:detail', args=[board_id]) + '?card=<card_pk>'`.
  `tasks` по-прежнему не импортирует модуль `boards`, только имя маршрута и
  связь `task.board_card`, как с `acts:detail` и `protocols:detail`.
- `tasks.views.task_detail`: задача `BOARD` перенаправляется на
  `board_card_url(task)`. Черновик «Выполнения» из сессии при этом **не
  забирается**: его заберёт панель (п. 3).
- Ни одна ветка `tasks/views.py` не рисует `tasks/detail.html` для задачи
  `BOARD`. Там, где сейчас при ошибке рисуется страница задачи
  (`complete_task_view`, `task_add_attachment`, удаление вложения), для
  `BOARD` текст ошибки уходит в `messages`, а пользователь перенаправляется на
  `board_card_url(task)`.
- Успешные загрузка, удаление вложения и `tasks:reopen` и так ведут на
  `tasks:detail`, то есть через перенаправление на доску. Проверь это тестами.
- `tasks:complete` для `BOARD` остаётся рабочим, но панель им не пользуется
  (п. 3).

## 2. Реестр задач и источник
- `describe_task_source()` для `BOARD`: подпись — название доски, ссылка —
  `board_card_url(task)`. Убери заглушку этапа 1.
- Поиск реестра (`tasks/selectors.py`, `_source_search_filter`) находит задачи
  `BOARD` по названию доски.
- Строки реестра ведут на `tasks:detail`, оттуда пользователь перенаправляется
  на доску. Менять адрес строки не нужно, но тест «клик по строке → доска с
  карточкой» должен быть.
- `select_related`/`prefetch_related` реестра и Excel-экспорта: подпись
  источника не должна добавлять запрос на каждую строку. Закрепи тестом через
  `assertNumQueries`, как сделано для соседних источников.

## 3. Панель карточки: завершение, вложения, возврат
Всё — в `templates/boards/includes/panel.html`, режим просмотра. Права
берутся из `tasks.permissions` (`can_complete_task`, `can_reopen_task`,
`can_upload_task_attachment`, `can_delete_task_attachment`) — своих правил у
досок нет.

- **Завершение** (`can_complete_task`):
  - форма «Выполнение»: textarea `execution_comment`, кнопка «Завершить»,
    `form[data-hotkey-submit]`;
  - POST на новый маршрут `boards:card_complete` → `complete_card()` →
    перенаправление на доску с открытой карточкой;
  - отказ сервиса (пустой комментарий и т.п.) — доска заново, панель открыта,
    текст в поле, ошибка видна;
  - начальное значение поля: черновик из сессии, иначе
    `task.execution_comment`. Так переоткрытая задача показывает прежний
    результат для правки, как на странице задачи;
  - помощники черновика (`_remember_execution_draft`, `_take_execution_draft`)
    вынеси из `tasks/views.py` в общий модуль `tasks/drafts.py` и используй
    их из обоих мест. Ключ сессии и поведение не меняются.
- **Вложения**: блок «Вложения» — та же разметка и те же маршруты, что на
  странице задачи:
  - `tasks:add_attachment`, `tasks:delete_attachment`, `tasks:download_attachment`;
  - загрузка — общим `[data-attachment-upload]` с переносом черновика
    `[data-attachment-carry-from]`;
  - удаление — через общий confirm-modal.

  Список карточек вложений сейчас строит `tasks.views._task_attachment_cards()`.
  Вынеси его в `tasks/presentation.py` (или `tasks/selectors.py`) и вызывай из
  обоих мест — второй копии быть не должно. Если общий фрагмент разметки
  вложений можно вынести из `templates/tasks/detail.html` в include и
  подключить в оба шаблона — сделай так.
- **Выполненная задача**: результат выполнения (`.user-text`), кто и когда
  завершил, вложения только на скачивание.
- **«Вернуть в работу»** (`can_reopen_task`): POST на существующий
  `tasks:reopen` через общий confirm-modal, как на странице задачи.
- **Отменённая задача**: панель только для чтения, без действий.
- Ссылку «Открыть задачу №N» убери. Номер задачи остаётся в шапке панели.
- Число запросов страницы доски с открытой панелью не зависит от числа
  карточек и вложений — тест.

## 4. Уведомление о назначении
- `Notification.EventType.BOARD_TASK_ASSIGNED` («Назначена задача на доске»),
  `TASK`-sourced. Миграция `notifications` — только изменение choices.
- `notifications.services.notify_board_task_assigned(task, actor, assignees)`
  в том же виде, что `notify_smk_task_assigned()`:
  - отказ для не-`BOARD` задачи;
  - `source_key=f'task:{task.pk}'`;
  - **`exclude_actor=True`**: человек, поставивший карточку себе, сам себя не
    уведомляет.
- Вызывается из `boards/services.py`, внутри той же транзакции, после того как
  задача и исполнители записаны:
  - `create_card()` — всем исполнителям;
  - `update_card()` — только **добавленным** исполнителям. Убранные и
    оставшиеся уведомления не получают.
- Тексты (`_task_event_text`, `_task_source_context`): «Назначена задача на
  доске «<доска>»», контекст «Доска «<доска>»». Источник в письме — через общий
  `describe_notification_source()`. Внутренний код `BOARD` никогда не
  показывается пользователю.
- Письмо: добавь событие в `EMAIL_ELIGIBLE_EVENTS`. Ссылка из письма и из
  колокольчика ведёт на `tasks:detail` и через перенаправление открывает
  доску — проверь тестом.
- Задача `BOARD` не порождает второго уведомления «задача назначена».

## 5. Тесты
- Перенаправления:
  - `tasks:detail` задачи `BOARD` → доска с `?card=`;
  - черновик из сессии доживает до панели и попадает в поле;
  - ошибки `tasks:complete` и `tasks:add_attachment` по задаче `BOARD` уводят на
    доску с сообщением, а не рисуют страницу задачи.
- Панель:
  - исполнитель завершает с комментарием, карточка в «Готово»;
  - пустой комментарий отклоняется, текст сохраняется;
  - не-исполнитель не видит формы, его POST отклоняется;
  - администратор видит «Вернуть в работу», после возврата карточка в прежней
    колонке, в поле прежний результат;
  - вложение загружается и удаляется через существующие маршруты и
    возвращает на доску;
  - у выполненной карточки вложения только на скачивание;
  - у отменённой — никаких действий;
  - число запросов постоянно.
- Реестр:
  - источник «название доски» со ссылкой на карточку;
  - поиск по названию доски находит задачу;
  - число запросов не растёт с числом строк.
- Уведомления:
  - создание карточки уведомляет исполнителей, кроме самого создателя;
  - `update_card` уведомляет только добавленных;
  - письмо поставлено в очередь; текст без `BOARD`;
  - ссылка ведёт на доску;
  - откат транзакции не оставляет уведомлений.
- Существующие тесты задач и уведомлений не ослабляются.
