# Задания, отчёты, проверки

Рабочая папка для поэтапной разработки: архитектор пишет задание, исполнитель
выполняет и пишет отчёт, архитектор проверяет. Это не документация проекта
(`docs/`), а переписка по задачам; `check_documentation` её не читает.

## Структура

```
tasksandreports/
  README.md                  — этот файл, правила для всех
  <проект>/
    plan.md                  — архитектурные решения и список этапов
    tasks/stage-NN.md        — задание этапа (пишет архитектор)
    reports/stage-NN.md      — отчёт исполнителя
    reviews/stage-NN.md      — проверка архитектора: вердикт и доработки
    reports/stage-NN-fix-K.md, reviews/stage-NN-fix-K.md — круги доработки
```

`NN` — двузначный номер этапа (`stage-01`), `K` — номер круга доработки.

## Где что лежит в Git

Архитектор и исполнитель работают в разных окружениях, общий у них только GitHub.

| Что | Кто пишет | Ветка |
| --- | --- | --- |
| `plan.md`, `tasks/`, `reviews/` | архитектор | `ccr-75191a56-5q4zpp` |
| `reports/` и код | исполнитель | своя ветка этапа |

## Исполнителю

1. Прочитай задание из ветки архитектора:

   ```
   git fetch origin ccr-75191a56-5q4zpp
   git show origin/ccr-75191a56-5q4zpp:tasksandreports/<проект>/plan.md
   git show origin/ccr-75191a56-5q4zpp:tasksandreports/<проект>/tasks/stage-NN.md
   ```

   Для доработки — ещё `reviews/stage-NN.md` (или `reviews/stage-NN-fix-K.md`).
2. Базовая ветка — та, что указана в задании (обычно ветка предыдущего
   принятого этапа или `main`, если он уже влит).
3. Выполни задание, соблюдая `AGENTS.md`.
4. Положи отчёт в `tasksandreports/<проект>/reports/stage-NN.md` **в своей
   ветке**, в том же коммите или следующим, и запушь. Задания и проверки в
   свою ветку не копируй.
5. В чат напиши только имя ветки и хеш коммита.

## Шаблон отчёта

```markdown
# Отчёт: <проект>, этап NN

1. Ветка и хеш последнего коммита.
2. Что сделано — кратко по разделам задания.
3. Изменённые и созданные файлы.
4. Миграции: имена, операции, зависимости; применяются ли с нуля.
5. Решения, которых не было в задании, и почему.
6. Отклонения от задания и почему.
7. Тесты: что добавлено; итоговые строки проверочных команд из задания
   (число тестов, OK/FAILED).
8. Известные проблемы, риски, сомнения.
```

## Архитектору

Проверка: `git fetch origin <ветка исполнителя>`, отчёт из
`reports/stage-NN.md` этой ветки, код — диффом против базовой ветки. Вердикт
пишется в `reviews/stage-NN.md` своей ветки: **принято** или **на доработку**
с пронумерованным списком того, что исправить.
