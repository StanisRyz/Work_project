{% load people %}{% comment %} A card's «Чек-лист» — the live block `[data-live-board-checklist]` on «Описание», with its own fingerprint (`checklist_revision`). It is not part of the guarded panel: ticking an item moves this block and the tile, never `panel_revision`, so it never raises the conflict banner over an edit being typed. The field «Добавить пункт» is the drawer's, below this block and outside every live block, so what is being typed there is never redrawn. Every control is an ordinary POST form, so the list works without JavaScript: the checkbox is a form's button posting the state it asks for (`done`), ↑ ↓ post a direction, «×» is a submit button the shared confirmation modal asks about first (`data-confirm-form`), and «Изменить» is a link (`&edit_item=`) to this same panel with that item as a form. While that form is open the live client leaves the block alone. With JavaScript (`static/js/board_checklist.js`) the checkbox posts through `fetch` and the page stays where it is; a refusal puts the tick back. «В подзадачу» (`card.can_add_subtask`: an open card that is no subtask, under the limit) turns an item into a subtask of this card through the shared modal; the item leaves the list. Who ticked an item and when is on its `title`. The controls are drawn only for whoever may change the list (`card.can_edit_checklist`: works on the board, the card is open); every route asks again. Without items and without that right nothing at all is drawn. {% endcomment %} {% if card.checklist or card.can_edit_checklist %}
