{% if user.is_authenticated %} {% comment %} «Смена пароля», in the project's own dialog styling. Deliberately plain inputs with the names `django.contrib.auth.forms.PasswordChangeForm` expects — `old_password`, `new_password1`, `new_password2` — rather than a rendered form: the dialog lives in the topbar of every page and must not need a bound form in every view's context. The server is the authority either way. `AppPasswordChangeView` verifies the current password, runs the project's password validators, hashes with `set_password()` and keeps the session signed in; a rejected submission lands on `accounts/password_change.html` with the errors beside the fields. The only client-side rule is the one worth catching before a round trip: the two new passwords not matching. Nothing here is a security check, and no password value is ever put into a URL or a data attribute. {% endcomment %}
