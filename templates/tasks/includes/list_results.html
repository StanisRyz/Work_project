The tabs and the filter form deliberately live outside, so a live refresh never replaces controls the user may be typing into. Drawn like the other registries: one line per row, sortable headers (`sortable_th`), the state as a `.status-badge` pill and the deadline through `includes/due_date.html` — an overdue task says so in its date, not with a red row. Every row comes pre-described by `tasks/presentation.py`: «Тип задачи» is the task's origin, «Источник» the document behind it with its own link, and «Статус» the real business state — for an approval queue entry the `ProtocolApproval` decision, never the queue's own «Выполнено». Fixed column widths, not the browser's guess: with an automatic layout a long wording claimed the whole table and squeezed every other column to a single character. The wording takes what the fixed columns leave and is cut to one line; the full text is on `title` and on the task page. {% endcomment %} {% if rows %}
